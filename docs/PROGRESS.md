## 2026-11-11 — сессия 1 (продолжение): этап 1 (движок под лонгформ) ✅

**Сделано** (коммит на каждый пункт, регрессии после каждого — чистые)
- **1.1 Размер кадра** — `TIMELINE.frame = { w, h }` (по умолчанию 720×1280). От него: CSS сцены/камеры/зерна, разрешение тайлов
  зерна (½ кадра), позиция субтитров (168 px от низа), центр камеры, viewBox сета `stage`, viewport/скриншот/scale в `render.mjs`.
  Тест `episodes/hd-test` (1920×1080, 12 с, гараж и трое героев, камеры сырыми координатами) — в регрессиях.
- **1.2 Рендер через pipe** — кадры из общей очереди процессов Chrome → буфер переупорядочивания → stdin ffmpeg (image2pipe).
  Окно забега `max(8, 3·jobs)` кадров + backpressure ffmpeg. Видео байт-в-байт как у старого пути через PNG-файлы (md5 потока).
  `--keep-frames` пишет PNG для отладки. Падение ffmpeg/Chrome → понятная первая причина, временный mp4 удаляется.
- **1.3 Шоу из сцен** — `show.mjs` + `shows/<name>/show.js`. Сцена = эпизод; рендер в `out/shows/<name>/` (видео без звука +
  `--audio-out` WAV ровно кадров×1600 сэмплов). Пересборка только изменённых сцен (хэш: файлы эпизода + относительные импорты
  + TIMELINE.scripts + движок + флаги кроме `--jobs` + Chrome + ffmpeg). Склейка: видео concat без перекодирования,
  звук встык с фейдами 8 мс на краях сцен и одним AAC на весь ролик.
- **1.4 Английский** — `TIMELINE.lang` (STT `--check`, счёт слогов), лимит строки субтитров от ширины кадра
  (720 → 3 слова/24 символа как было, 1920 → 6/42; `TIMELINE.subMax` перекрывает), цифры↔слова в `--check` для en.
  `--voice` у немой сцены пропускается. Тест: `episodes/hd-test-b` — две английские реплики (стоковые голоса Fish «Adrian»,
  «Ethan» — только для теста), обе проходят `--check`.

**Критерии этапа — проверено**
- Старые эпизоды = эталоны (`regress.sh`); превью tolyan (`--sfx`) и garazh (`--sfx --voice`) байт-в-байт как на этапе 0 (оба потока).
- 192 с 1920×1080 (`hd-test-long`): 472 с рендера, Linux-диск +5 МБ, C: +817 МБ (= сам mp4), RAM +1.6 ГБ. Раньше было бы ≈19 ГБ PNG.
- Шоу `hd-test` из 3 сцен: 705 декодированных кадров = кадры сцен по порядку; метки tick в каждой сцене на месте (±0.4 мс);
  на стыке после обрезанной сцены (4.51 с → 4.5 с) скачок без фейдов 5.2× от максимума внутри сцены, с фейдами ≈0;
  перестановка сцен — 3 с (всё из кэша); правка одной сцены — пересобирается только она.
- Английская реплика проходит `--check`.

**Решили (и почему)**
- `--jobs` по умолчанию оставили 4: замер 4/6/8 на 1080p — 6 даёт +7 % в превью и 0 в чистовике (CPU и так загружен), а памяти больше.
  Результат от числа процессов не зависит (md5 одинаковые).
- Сцены не режем на куски для параллельного кодирования: лишние ключевые кадры на стыках, теряется байт-в-байт.
- Звук шоу кодируется в AAC один раз: склейка готовых AAC-кусков даёт паузы priming на стыках.
- Пресеты камер (`wide`, `cu:` …) пока настроены под вертикаль — горизонтальные пресеты на этапе 5.

**Цифры**
- 1080p, `hd-test` 12 с: превью (dsf 1, veryfast) ≈ 11 кадр/с; чистовик (dsf 2, slow) ≈ 3.2 кадр/с.
  Узкое место чистовика — съёмка 4K при dsf 2, не x264 (dsf 2 + veryfast — 3.4 кадр/с; dsf 1 + slow — 7.2 кадр/с).
- Прогноз на 10 мин: превью ≈ 27 мин, чистовик dsf 2 ≈ 1.5 ч, чистовик dsf 1 ≈ 42 мин.
- mp4 тяжёлые из-за зерна: превью 1080p ≈ 4.2 МБ/с (192 с — 812 МБ).
